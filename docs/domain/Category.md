# Category Entity Guide

## Overview

`Category` represents a validated classification that can be referenced by products. Examples in this business could include `Projector`, `Screen`, or `Accessory`.

Source files:

- [`Category.cs`](../../Domain/Categories/Category.cs)
- [`CategoryName.cs`](../../Domain/Categories/ValueObjects/CategoryName.cs)
- [`InvalidCategoryNameException.cs`](../../Domain/Categories/Exceptions/InvalidCategoryNameException.cs)

## Business Purpose

The entity gives the catalog a reusable category identity instead of storing an unrestricted category string on every product. A product can hold the category's `Guid` in `Product.CategoryId`.

Current business capabilities are intentionally small:

- Create a category with a valid name.
- Obtain a stable category ID and creation timestamp from `BaseEntity`.
- Reference that category from any number of products.

The model does not currently include category renaming, hierarchical categories, category deletion behavior, display ordering, or uniqueness checking.

## State

| Property | Type | Meaning | Mutation |
|---|---|---|---|
| `Id` | `Guid` | Unique entity identity | Generated by `BaseEntity` |
| `CreatedAt` | `DateTime` | UTC creation timestamp | Generated by `BaseEntity` |
| `IsDeleted` | `bool` | Soft-delete state | Protected setter; no category behavior currently changes it |
| `CategoryName` | `CategoryName` | Validated display/business name | Set only during construction |

## Creation

Categories are created through the public factory:

```csharp
var category = Category.Create(
    new CategoryName("Projectors"));
```

The constructor is private, so normal callers cannot create the entity without going through `Create`.

## Category Name Rules

`CategoryName` is an immutable record that owns normalization and validation.

| Input rule | Result |
|---|---|
| `null`, empty, or whitespace-only | Rejected |
| Leading or trailing whitespace | Removed with `Trim()` |
| More than 50 characters after trimming | Rejected |
| 1 to 50 non-whitespace characters | Accepted |

Example normalization:

```csharp
var name = new CategoryName("  Projectors  ");

// name.Value == "Projectors"
```

Because `CategoryName` is a record, two instances with the same normalized value use value-based equality.

## Invariants

Once a valid category has been created:

- It always has a generated non-empty identity under normal construction.
- Its name is not blank.
- Its name is no longer than 50 characters.
- Its name cannot be changed through the current public API.

## Failures

| Operation | Invalid condition | Exception |
|---|---|---|
| `new CategoryName(value)` | Blank value | `InvalidCategoryNameException` |
| `new CategoryName(value)` | Normalized value exceeds 50 characters | `InvalidCategoryNameException` |

`Category.Create` accepts the typed value object and does not perform a separate null check. Callers should construct and pass a valid `CategoryName`.

## Relationship to Product

`Category` does not own a product collection. The relationship is represented in the opposite direction:

```text
Category.Id <----- Product.CategoryId?
```

`Product.AssignCategory` rejects `Guid.Empty`, but the domain does not verify that the category exists. That lookup belongs in an application service or repository-backed command handler.

Removing a category from a product sets `Product.CategoryId` to `null`; it does not delete the category.

## Technical Design

- Namespace: `Domain.Categories`
- Entity kind: sealed entity
- Base class: `BaseEntity`
- Creation style: static factory plus private constructor
- Name type: immutable record value object
- Persistence relationship: identifier reference only
- Domain dependencies: `Domain.Abstractions` and category value objects

The entity has no parameterless constructor. Any persistence integration must support constructor binding or provide an explicit mapping strategy without weakening the public domain API.

## Runtime Integration Status

The current API does not persist this `Category` entity and has no category controller or `DbSet<Category>`. The legacy `Shared.Models.Product` stores category as a plain string.

As a result, category identity and `CategoryName` validation are domain-model capabilities but are not yet enforced by the running API.

## Recommended Test Scenarios

1. Creating a category generates an ID and UTC creation timestamp.
2. A normal name is preserved.
3. Leading and trailing spaces are trimmed.
4. Empty and whitespace-only names are rejected.
5. A 50-character name is accepted.
6. A 51-character name is rejected.
7. Two equal normalized category names compare equal as value objects.
8. A product can reference the category ID and later remove that reference.

## Current Limitations

- No rename behavior.
- No category hierarchy or parent category.
- No uniqueness rule for category names.
- No protection against deleting a category referenced by products.
- No domain-level category existence check during assignment.
- No API or persistence mapping for the new entity.
